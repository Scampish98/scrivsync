# ScrivSync

Ручной обмен проектом Scrivener через один ZIP-архив на Яндекс Диске.
Одна Go-программа, две команды: `push` и `pull`. Пути и токен задаются в `configs/config.yaml`.

## Структура репозитория

```text
scrivsync/
  AGENTS.md
  configs/
    config.example.yaml  # шаблон в Git
    config.yaml          # личные настройки; исключены из Git
  bin/                   # локальные сборки; исключены из Git
  go.mod
  go.sum
  *.go
```

`.idea/` и `vendor/` также исключены из Git. Правила работы над проектом находятся
в `AGENTS.md`.

## Быстрый запуск на Mac

Репозиторий содержит исходники и тесты. Для сборки нужен Go 1.26 или новее.
Из корня репозитория выполните:

```sh
go build -o bin/scrivsync ./cmd/scrivsync
```

Скопируйте `configs/config.example.yaml` в `configs/config.yaml`, если у вас ещё нет настроек:

```sh
test -f configs/config.yaml || cp configs/config.example.yaml configs/config.yaml
chmod 600 configs/config.yaml
```

Перейдите в папку `bin`. Примеры ниже выполняются из этой папки.

Откройте `configs/config.yaml` в корне репозитория и заполните три поля:

```yaml
local_path: '/Users/you/Documents/Novel.scriv'
remote_path: 'disk:/Scrivener/Novel.zip'
token: 'ваш-токен-Яндекс-Диска'
```

Шаблон содержит пустой токен: его нужно заполнить.
Программу можно собрать в корень репозитория или в `bin/`: в обоих случаях она ищет
`configs/config.yaml` в корне репозитория, независимо от текущей папки Терминала.
При запуске через символическую ссылку расположение определяется по настоящему
исполняемому файлу. Переменные окружения с токеном не читаются.

Токену нужны права чтения и записи в используемую папку Яндекс Диска. Конфиг содержит
токен открытым текстом; он исключён из Git. Значения токена не выводятся даже при ошибке
разбора YAML. Держите программу и конфиг вне папки проекта: программа проверяет это,
чтобы конфиг не попал в архив.

```sh
./scrivsync push
./scrivsync pull
./scrivsync --help
```

`remote_path` указывает на **архив**, не на папку. Пробелы и кириллица поддерживаются.
Поддерживаются `disk:/Scrivener/Novel.zip` и `app:/Scrivener/Novel.zip`.
Для архива в корне папки приложения можно указать `app:/Novel.zip`.
Короткая запись `/Scrivener/Novel.zip` по-прежнему означает `disk:/Scrivener/Novel.zip`.
Временный архив и папка `Backups` создаются рядом с архивом в том же пространстве путей.
`local_path` может быть абсолютным или относительным: относительный путь отсчитывается
от папки `configs/`. Сокращение `~` не используется: укажите полный путь.
Родительская локальная папка должна существовать. Сам проект при первом `pull`
может отсутствовать. Отсутствующие облачные папки `push` создаёт автоматически.

macOS может потребовать разрешение Терминалу на доступ к «Документам» или другой
защищённой папке. При отказе программа завершится с ошибкой.

## Windows

На Windows из корня репозитория выполните в PowerShell:

```powershell
go build -o bin/scrivsync.exe ./cmd/scrivsync
if (-not (Test-Path configs/config.yaml)) { Copy-Item configs/config.example.yaml configs/config.yaml }
```

Заполните `configs/config.yaml` с локальным путём Windows и тем же облачным архивом:

```yaml
local_path: 'C:\Writing\Novel.scriv'
remote_path: 'disk:/Scrivener/Novel.zip'
token: 'ваш-токен-Яндекс-Диска'
```

Одинарные кавычки сохраняют обратные слеши Windows без экранирования.
Запускайте в PowerShell:

```powershell
cd bin
.\scrivsync.exe pull
.\scrivsync.exe push
```

После `pull` откройте `.scrivx` внутри локальной папки проекта. Для обмена архивами
штатный клиент Яндекс Диска не нужен. Чтобы обеспечить одинаковую обработку дат,
рекомендуется создавать и распаковывать архивы этой программой на обоих устройствах.
Windows-сборка проверена компиляцией; запуск на Windows не проверялся.

## Рабочий порядок

1. На первом устройстве закройте Scrivener и выполните `push`.
2. Дождитесь сообщения `Push завершён`.
3. На втором устройстве закройте Scrivener, выполните `pull`, дождитесь успеха.
4. Откройте проект и работайте. После работы повторите процедуру в обратную сторону.

Обе команды отказываются работать, пока запущен Scrivener. Не открывайте приложение
во время передачи. Проверка процесса не запрещает его запуск и не является блокировкой
самого Scrivener. Одновременные команды на разных компьютерах не поддерживаются.
На одном компьютере наложение команд для одного локального проекта блокируется ОС.

`push` всегда публикует выбранный локальный проект, даже если облачный архив новее.
Предыдущий облачный архив сохраняется. Перед началом работы на другом компьютере
сначала делайте `pull`, чтобы не отправить устаревшую копию.

## Push

1. Проверяет и упаковывает весь проект, включая скрытые файлы и пустые папки.
   В ZIP хранится одна корневая папка проекта. Даты изменения сохраняются в UTC
   с точностью до секунды. Символические ссылки и специальные файлы запрещены.
2. Проверяет, что исходный проект не изменился при упаковке.
3. Читает метаданные текущего облачного ZIP и проверяет, свободно ли имя бэкапа.
4. Загружает новый архив под временным именем, сверяет размер и SHA-256 с API.
5. Перемещает старый архив в соседнюю папку `Backups`, используя его облачное
   время **создания**, переведённое в UTC:

   ```text
   disk:/Scrivener/Novel.zip
   disk:/Scrivener/Backups/Novel_2026-09-30T14-30-00Z.zip
   ```

6. Перемещает новый архив на основной путь и проверяет результат.

У имени бэкапа нет дополнительного идентификатора. Совпадение имени — ошибка,
существующий бэкап не перезаписывается. Это относится и к двум созданиям в одну секунду.
Только технические временные файлы имеют уникальные имена.

Первый push выполняется без облачного бэкапа. Старые бэкапы не удаляются автоматически.
На время двух перемещений основной путь может отсутствовать; при сбое см. восстановление.

## Pull и конфликты

1. Скачивает архив, сверяет SHA-256 и размер, распаковывает во временную папку.
2. Проверяет CRC файлов ZIP, допустимость путей и восстанавливает даты изменения.
3. Сравнивает все локальные файлы со скачанными по содержимому и времени.
4. При любом конфликте выводит все обнаруженные конфликтные пути и прекращает работу.
5. Повторно проверяет неизменность локального проекта и облачного архива.
6. Сохраняет прежнюю локальную папку как бэкап, устанавливает подготовленный проект.

| Ситуация | Результат |
|---|---|
| Содержимое файла совпадает | Конфликта нет при любых датах |
| Разное содержимое; локальный файл новее более чем на 2 секунды | Конфликт |
| Разное содержимое; разница дат не превышает 2 секунд | Конфликт |
| Разное содержимое; архивный файл новее более чем на 2 секунды | Принимается архивный файл |
| Файл или папка есть только локально | Конфликт |
| Файл есть только в архиве | Добавляется |
| По одному пути на одной стороне файл, на другой папка | Конфликт |

Полностью совпадающий проект не заменяется. Даты неизменившихся локальных файлов
при таком пропуске не меняются. При установке проекта восстанавливаются даты из ZIP,
а не дата его создания или скачивания. Сравнение дат предполагает правильно настроенные
часы устройств; изменения с вручную сохранённой старой датой могут не распознаваться
как более свежие. Автоматического слияния нет.

При конфликте исходный проект остаётся на месте. Скачанный ZIP, распакованная копия
и отчёт сохраняются в отдельной папке `run-...` внутри служебной папки рядом с проектом.
Программа выводит полный путь к данным и к `report/index.txt`.

```text
.Novel.scriv.scrivsync-state/
  run-.../
    project.zip          # скачанный и проверенный архив
    project/             # распакованная копия
    report/
      index.txt          # причины конфликтов и соответствие логов исходным путям
      000001.diff.txt    # один отличающийся путь — один лог
      000002.diff.txt
```

Отчёт включает все различия содержимого и структуры, в том числе изменения,
которые сами по себе не блокируют pull. Файлы с одинаковым содержимым и разными
датами не включаются. В каждом логе указаны исходный путь, наличие каждой версии,
тип объекта, даты, размеры и SHA-256. В построчном диффе `-` обозначает локальную
версию, `+` — скачанную. Добавления и удаления также видны в диффе.

RTF сравнивается как исходный код: в нём видны управляющие команды форматирования
и экранированные символы. Это не сравнение только текста, видимого в Scrivener.
Для двоичных файлов и текста не в UTF-8 выводятся метаданные. Построчный дифф
также пропускается, если одна из версий больше 2 МиБ или содержит 50000 переносов
строк и более; причина явно записывается в соответствующий лог.

Повторный конфликт сохраняется в новой папке; предыдущие отчёты не перезаписываются.
Ошибка создания отчёта не удаляет скачанные данные: программа указывает причину,
а доступная часть отчёта остаётся на диске. Если файл изменился во время подготовки
диффа, вместо недостоверного сравнения записывается ошибка.

Для конфликта журнал установки `operation.json` не создаётся: следующий `pull`
снова скачает текущий архив и проверит проект. Разрешите различия вручную и повторите
команду. После разбора папку с диагностикой можно удалить вручную; автоматически
она не очищается. Не удаляйте локальные уникальные файлы без сохранения копии.

Формат ZIP: одна корневая папка, без соседней `__MACOSX` и без служебных файлов
вне проекта. Имя корневой папки в архиве может отличаться от локального.
Проект принимается только с переносимыми между Mac и Windows именами: без ссылок,
зарезервированных Windows имён, конфликтов регистра, `..`, абсолютных путей и т. п.
Имена в разных формах Unicode на разных файловых системах отдельно не нормализуются.
Лимиты распаковки: 100000 записей и 100 ГиБ суммарного распакованного содержимого.

## Локальные бэкапы и восстановление

Рядом с проектом создаётся скрытая служебная папка:

```text
Writing/
  Novel.scriv/
  .Novel.scriv.scrivsync-state/
    lock
    operation.json       # существует только при незавершённой операции
    run-.../             # временная копия операции или сохранённая диагностика конфликта
    Backups/
      Novel.scriv_2026-09-30T14-30-00Z/
```

В локальном имени бэкапа используется время начала установки в UTC. При совпадении
имени программа останавливается. Служебная папка не находится внутри проекта и не
попадает в ZIP. Бэкапы остаются до ручного удаления.

При ошибке сети или прерывании процесса **повторите ту же команду, сохранив пути в configs/config.yaml**.
Журнал позволяет продолжить push после перемещения старого архива и pull между
двумя перемещениями папок. Если операция фактически завершилась, но ответ сервера
потерялся, программа проверит результат, не перезаписывая бэкап.

Восстановленный push отправляет ранее подготовленный снимок. Если после сбоя проект
редактировался, после восстановления выполните push ещё раз для новых изменений.
Обнаружив неожиданные изменения, программа останавливается и сохраняет файлы для
ручного восстановления. Журнал содержит пути, но не токен из конфига.
При наличии `operation.json` не удаляйте журнал и указанную в нём папку `run-...`,
пока операция не восстановлена или её данные не сохранены отдельно.

Если локальная замена прервалась и основной папки нет, предыдущий проект находится
в указанной в журнале папке `Backups`. До восстановления не открывайте Scrivener.
На Windows гарантии сохранения переименований при внезапном отключении питания
зависят от файловой системы; это не полноценная транзакция файловой системы.

Коды завершения: `0` — успех, `2` — конфликт при pull, `1` — остальные ошибки.
Одна команда ограничена одним часом. При сетевом сбое повторите команду вручную.
Токен и подписанные ссылки передачи не печатаются в ошибках HTTP.

## Сборка и проверки

Нужен Go 1.26 или новее:

Зависимости фиксируются в `go.mod` и `go.sum` и загружаются Go при первой сборке.
Папка `vendor/`, если создана локально, в Git не хранится.

Для удобства в корне репозитория есть Makefile (нужен `make`):

```sh
make                 # список команд
make test            # все тесты
make vet             # статическая проверка кода
make check           # тесты и go vet
make build           # приложение для текущей платформы в bin/
make build-all       # macOS arm64 и Windows amd64
make fmt             # форматирование Go-кода
make clean           # удаление собранных исполняемых файлов из bin/
```

Отдельные платформы можно собрать через `make build-macos` и `make build-windows`.
После `make build` на macOS запускайте `./bin/scrivsync push` или `./bin/scrivsync pull`.
Цели Makefile для проверок и сборки не запускают синхронизацию.

Без `make` доступны те же команды Go:

```sh
go test ./...
go vet ./...
go build -o bin/scrivsync ./cmd/scrivsync
```

После сборки заполните `configs/config.yaml` в корне репозитория.
Для обычного запуска используйте собранную программу: `go run` помещает исполняемый
файл во временную папку, где пользовательского конфига нет.

Автоматические тесты проверяют упаковку/распаковку, даты, границу в две секунды,
конфликты, сохранение бэкапов, восстановление при сбоях, опасные ZIP и работу
HTTP-клиента с моделируемыми ответами API. Они не обращаются к Яндекс Диску.
Также проверяются поиск конфига, YAML, относительные пути и отсутствие токена в ошибках.
Работа с настоящим аккаунтом пока не проверялась.

Программа использует REST API `https://cloud-api.yandex.net/v1/disk` и требует
наличия SHA-256 в метаданных файла для проверки целостности. Если API не предоставляет
контрольную сумму, операция останавливается. Настоящий проект рекомендуется впервые
проверять через отдельную копию и отдельный облачный путь.

## Структура исходников

- `cmd/scrivsync/` — запуск CLI, обработка команды и подготовка приложения.
- `internal/config/` — чтение YAML и проверка путей.
- `internal/sync/` — сценарии обмена: `push.go`, `pull.go`, журнал восстановления.
- `internal/yandex/` — HTTP-клиент Яндекс Диска, передача файлов и метаданные.
- `internal/archive/` — ZIP, снимки файлов и проверка конфликтов.
- `internal/report/` — отчёты о конфликтах и построчные диффы.
- `internal/lock/` — блокировка проекта и проверка запущенного Scrivener на macOS/Windows.
- `internal/fileutil/` — закрытие файлов, очистка и сброс изменений папок на диск.
- `internal/ctxio/` — чтение и ожидание с поддержкой отмены.
- `configs/` — пример конфига и личные настройки.

Ошибки закрытия ресурсов и очистки временных данных, которые нельзя вернуть
вызывающему коду, записываются через `log/slog` в stderr. Ошибки записи, влияющие
на сохранность архива или журнала, возвращаются и останавливают операцию.
